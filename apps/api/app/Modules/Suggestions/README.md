# Suggestions

Things to do that make a day better, each with a category (focus, growth, health, wellbeing, social, fun) and a status (new, accepted, done, dismissed). `accepted_at`, `done_at` and `dismissed_at` record when each status was reached, so Reports and Metrics can count them by day.

- Driven by sources in `Sources/`, each a `Suggester` that reads the user's data: `PlanTomorrow` (apply a schedule when tomorrow is empty), `OverdueTasks`, `StalledTasks` (in progress for a week with nothing logged), `QuietGoals` (an active goal with nothing finished this week), `CelebrateGoals` (a goal completed in the last two weeks with no achievement), `StreakMilestones` (7, 14, 30… days of activity in a row), `UnreviewedWeek` (Monday to Wednesday, last week had work but no review), `EveningJournal` (no entry after 6 pm) and `IdeaLibrary`, which tops up ideas from `Config/suggestions.php`. A new source is one class added to `SuggestionEngine::sources()`.
- `IdeaLibrary` also draws on a shared pool of ideas fetched from the internet (`suggestion_ideas`, `PooledIdea`), so the library does not only cycle through the fixed list. Every six hours the scheduler runs `suggestions:fetch-ideas`, which asks the feed in `suggestions.feed.driver` for a few ideas. By default that is `Feeds/LocalClaude.php`, which runs the Claude Code CLI on this machine (Haiku, about $0.001 a run). It runs headless with no tools, MCP servers, settings or saved session, from an empty folder under `storage/framework`, with a 120 s timeout and a $0.05 spending cap, and the answer must match a JSON schema. The CLI is found on the PATH, in `~/.local/bin` or `/usr/local/bin`, or at `SUGGESTIONS_CLAUDE_BIN`, and the model is set with `SUGGESTIONS_CLAUDE_MODEL`. Set `SUGGESTIONS_FEED_DRIVER=bored` to use `Feeds/BoredApi.php`, the keyless [Bored API](https://bored-api.appbrewery.com/random), instead. Only the scheduled command reaches the internet, so refreshes never wait on it, and with an empty pool the built-in library carries on alone. An idea gets in only if it passes every check, and nothing is repaired:
  - **Transport** (`BoredApi`): HTTPS only, no redirects, 3 s connect and 5 s total timeouts, and a reply must be JSON of at most 2 KB. Only the activity text, type and duration are read; links and other fields are ignored. The first failed or malformed reply ends the run quietly.
  - **Activity** (Bored API): a type mapped in `suggestions.feed.types` (charity is left out), kid friendly, priced at most `max_price`, without major accessibility challenges, and done within minutes or hours.
  - **Text** (`IdeaPool`, every feed, including Claude): only letters, digits, spaces, apostrophes, hyphens and commas (no markup, links, symbols or emoji); at most `max_length` characters and 2 to 12 words; sentence case with no capitals after the first letter, which rules out names, brands and shouting; it opens with a verb from `suggestions.feed.verbs`; and it has no word from `suggestions.feed.blocked` (substances, nightlife, risk, money, driving, medical, pranks, pets, property the user may not have, and non-local or misspelt items).
  - **Repeats**: ideas are keyed by slug (`web-…`), so each is stored once and none repeats a built-in idea. The newest `keep` stay. Each run re-checks the whole pool, so tightening a rule also removes ideas already stored and withdraws their open suggestions.

  Swap the feed with a class implementing `Contracts/IdeaFeed`, or turn it off with `SUGGESTIONS_FEED=false`.
- A key per suggestion stops repeats; open insights whose reason has passed are withdrawn. Library ideas are picked one category at a time in a daily order, rotate out after `rotate_after_days` untouched, and rest for `cooldown_days` once done or dismissed before they can return.
- `GET /api/v1/suggestions?status=` lists them (`new` by default, `all` for the catalogue) without changing anything; `POST /suggestions/refresh` refreshes now, or with `stale: true` only if this hour's refresh hasn't run (the page does this when it opens); accepting is idempotent and atomic; `POST /suggestions` adds your own; `PATCH` and `DELETE /suggestions/{id}` manage them.
- `POST /suggestions/{id}/accept` (optional `date`) acts on one: applies the schedule, records an achievement, adds a task due that day, or for `open` suggestions (a route and optional params) just marks it accepted.
- Owns `suggestions`, `suggestion_ideas` and the Suggestions settings.

Depends on Users, Settings, Tasks, Goals, Journal, Planner, Reviews, Achievements and Metrics (activity streaks).
